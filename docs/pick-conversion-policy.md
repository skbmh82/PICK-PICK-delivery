# PICK 토큰 전환 정책 (테스트넷 → 메인넷)

> 초안 · 메인넷 토큰 발행 정책 확정 시 수치를 최종 확정합니다.
> 목적: 테스트넷에서 적립한 PICK을 **공정하게** 메인넷 보상으로 환산하고, 어뷰징(다계정·파밍)을 배제한다.

---

## 1. 대원칙

1. **1:1 전환 금지** — 테스트넷은 다계정이 자유롭고 메인넷은 KYC 1인 1계정이라, 잔액을 그대로 넘기면 파밍이 곧 이득이 된다. 따라서 **출처별 가중치 + 어뷰징 제외 + KYC 게이트**를 적용한다.
2. **KYC 게이트** — 메인넷 전환은 **KYC 인증된 실계정**만 대상. 한 사람의 여러 테스트넷 계정 중 실명 인증되는 1개만 인정된다.
3. **진짜 활동 우대** — 실제 주문·리뷰 등 위조가 어려운 활동에서 나온 PICK을 높게, 자동화·복제가 쉬운 출석/초대를 낮게 평가한다.
4. **어뷰징 제외** — 감사(`scripts/pick-abuse-audit.sql`)에서 걸러진 파밍 계정·클러스터는 전환 대상에서 제외한다.
5. **"잔액"이 아니라 "출처" 기준** — 지갑 잔액은 **보내기(전송)로 옮길 수 있으므로**, 전환은 각 계정이 **실제로 만든 활동에서 나온 PICK**만 인정한다. **전송받은 PICK은 전환에서 제외**한다. (다계정→단일계정 몰빵(consolidation) 우회 차단 — "제일 많은 계정만 살려서 가면 된다"를 무력화)

---

## 2. 출처별 전환 가중치 (초안)

| 출처 | 위조 난이도 | 가중치(w) | 근거 |
|------|:---:|:---:|------|
| 🛵 라이더 배달 수익 | 매우 높음 | **1.0** | 실제 배달 수행 = 위조 최난이도 (배달비 전액 = amount_pick) |
| 🛒 실주문 결제·리뷰 보상 | 높음 | **1.0** | 실제 이용 = 유용성 검증의 핵심 |
| 🎁 초대 보상(정상) | 중간 | **0.5** | 양방향 차단 후에도 남는 조작 여지 |
| 🗓️ 출석 활동 보너스(+50) | 중간 | **0.5** | 최근 실주문 조건이 붙어 파밍 난이도↑ |
| 🗓️ 출석 탭(기본) | 낮음 | **0.2** | 자동화·다계정 복제 용이 |
| 📤 전송받은 PICK (보내기 수신) | — | **0 (제외)** | 잔액 이동일 뿐 활동 아님 · 몰빵 우회 차단 |

> 값은 예시이며, 메인넷 발행량·목표 분배에 맞춰 조정한다.
> ⚠️ **라이더 배달 수익 주의**: 현재 배달비 100%가 라이더 PICK으로 발행되고 플랫폼 수수료가 0이다. 메인넷 정산에선 **수수료 정책(예: 라이더 80% / 플랫폼 20%)** 을 먼저 정하고, 그 순수익 기준으로 가중해야 한다. 또한 배달비를 임의로 높여 자기배달로 파밍하는 것을 막기 위해 **자기거래 링(4-②) 제외**를 반드시 적용한다.

---

## 3. 산정 공식

계정별 환산 포인트:

```
convertible(user) =
    Σ_source ( pick_from_source × weight_source )        // 출처별 가중 합
    × eligibility(user)                                   // 어뷰징/미인증이면 0

mainnet_reward(user) = convertible(user) × GLOBAL_RATIO   // 발행 정책상 최종 배율
```

- `eligibility(user)` = KYC 인증 && 어뷰징 미해당 시 1, 아니면 0
- `GLOBAL_RATIO` = 메인넷 발행 정책에서 정하는 전체 배율 (예: 총 분배량 ÷ 전체 convertible 합)

---

## 4. 어뷰징 제외 절차

메인넷 전환 스냅샷 시점에 `scripts/pick-abuse-audit.sql`를 실행해 아래를 검토·제외한다.

1. **양방향(서로) 초대 쌍** — 자기초대 파밍 (※ 적립 단계에서 이미 차단하지만 과거분 점검)
2. **자기거래 링(self-dealing)** — 한 사람이 유저·사장님·라이더 계정을 만들어 "내 주문 → 내 가게 → 내 배달"로 배달비 PICK 자가 발행. 라이더 배달의 **고객·가게 다양성이 극단적으로 낮으면** 폐쇄 루프 의심 → 해당 라이더 수익 제외.
3. **전송 몰빵(consolidation)** — 여러 계정에서 한 계정으로 PICK을 모은 흔적. **전송받은 PICK은 원칙적으로 전환 제외**하되, 한 계정이 **다수 발신자로부터 수신**했으면 파밍 클러스터로 간주.
4. **유사 username + 근접 가입시각** — 한 사람의 다계정 순차 생성 정황
5. **PICK 보유 but 주문 0** — 순수 파밍 의심 (활동 가중치로 자연 감쇠되지만 극단치는 수기 검토)
6. **초대 보상 상위 랭킹** — 비정상 집중 여부 확인
